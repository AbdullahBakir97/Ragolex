# SDKs

Clients for the Ragolex API, generated from its OpenAPI schema, so they cover every endpoint and stay in step with the API:

| | Package | |
|---|---|---|
| [TypeScript](typescript/README.md) | `@ragolex/client` | Every endpoint typed from the schema; uploads, streamed answers and jobs as methods. Node 20+ and browsers. |
| [Python](python/README.md) | `ragolex-client` | A method per endpoint with Pydantic models, sync and asyncio; uploads, streamed answers and jobs. Python 3.10+. |

Both send the API key as `Authorization: Bearer ragolex_…`, raise an error carrying the API's `signal` (such as `project_not_found`) and its HTTP status for error responses, and stream answers as they are written.

## How they are made

[`openapi.json`](openapi.json) is the API's schema, as served at `/openapi.json`. Each operation is named after its route function (`upload_data`, `search_project`, `list_files`…), and the SDKs name their methods after it.

- The TypeScript types (`typescript/src/schema.ts`) are generated by [openapi-typescript](https://openapi-ts.dev); the client is [openapi-fetch](https://openapi-ts.dev/openapi-fetch/), typed by them.
- The Python models and methods (`python/src/ragolex_client/models.py` and `_operations.py`) are generated by [`python/generate.py`](python/generate.py), which has no dependencies.

What the schema cannot describe is written by hand beside the generated code: multipart uploads, Server-Sent Events, and waiting for jobs.

## After changing the API

```bash
ragolex openapi --output sdk/openapi.json      # from the repository root
(cd sdk/typescript && npm run generate)
(cd sdk/python && python generate.py)
```

CI fails when any of these is out of date: `tests/test_openapi.py` compares `openapi.json` with the API, and the SDK jobs regenerate the code and compare it with the committed one.

## Compatibility

The SDKs follow the API's `/api/v1`: fields and endpoints are only added within it. Responses are read leniently, so a client keeps working with a newer server: unknown fields are kept (`model_extra` in Python), and values of the API's enumerations, such as signals, are read as strings even when they are new. A newer Python client reads a nullable field an older server does not send yet as `None`.
